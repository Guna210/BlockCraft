### M04 polling cause and correctness

The original path queried older fences with synchronous `getSyncParameter`, then drained errors even when newer submitted GPU work remained pending. That synchronous read could stall on newer work, starving frame production and streaming progress. Game code now performs a zero-timeout native poll of the latest submitted fence. If it signals, all older fences are complete too, and reading errors cannot wait for newer submitted work. If it does not, the unchanged four-frame bound still forces error coverage. Final drains, per-draw checks, flushes and every draw remain. Existing query-only adapters keep their original contract. Three owned regression tests exercise latest-fence retirement, the forced bound and fence deletion; all eight unchanged fence tests pass. Changes are confined to `src/main.ts`, `src/render/fenced-error-drain.ts` and M07b’s own tests. This explains why the change is correct independently of the observed focused recovery from eight to 12 frames and the successful frustum check. Neither M04 frame-count nor frustum failures are exceptions; any recurrence in final verification will be reported explicitly.
