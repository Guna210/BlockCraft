## What was built

`Inventory` extends storage to 41 slots while preserving hotbar/main indices.
It owns the mouse cursor and synchronous model operations. Operations do not use
DOM, input handlers or rendering. Each move checks per-item conservation and
valid stack/equipment bounds. Drop checks the exact expected count reduction.
`dropInventoryStack` is the separate world boundary: spawn through the M07b
manager first, remove the stack only on success. No key or UI binding is added.

Registry categories add five families across all A.2 tiers, iron shears, bow,
shield, Ember Flint; copper/iron armor; A.4 resources and named A.2 ingots; all
A.5 foods with hunger/saturation; appendix materials. No recipe, defense or wear
behavior is introduced. World-drop sprite textures satisfy the existing M07b
renderer contract; these are not an inventory icon atlas.

Changes to M07b-owned code/data are limited to completing its inventory/item
registry and debug domains, adding the required world-drop textures, and fixing
clay/wall-torch loot. Existing M07b tests are unchanged. No sky, clouds, weather,
verification harness or earlier milestone's tests are changed.

## Notes for dependent tasks

- Slots: hotbar 0–8, main 9–35, head/chest/legs/feet 36–39, offhand 40.
- `leftClick`, `rightClick`, `shiftClick`, `drag`, `doubleClick` act on the model.
  Double collect requires a nonempty cursor. Drag takes distinct eligible targets
  in input order; capacity truncation stays on cursor rather than redistributing.
- Equipment extraction completes main storage routing before trying hotbar.
  Offhand accepts any item; each armor slot accepts only its declared type.
- `drop(target, whole)` is pure model removal. M09b should call the separate
  `dropInventoryStack(inventory, manager, position, target, whole)` adapter to
  preserve items if the bounded world pool is exhausted. Targets are slot numbers
  or `'cursor'`; default drops one.
- `snapshot()` preserves M07b's 36-slot storage snapshot; use `snapshot(true)` for
  equipment. Debug `getInventory()` returns all 41, with the old entry shape.
  Debug `getInventoryCursor()` and model `cursorSnapshot()` return a detached
  cursor stack without a slot field.
- `counts()` and `assertInvariant(beforeCounts)` include equipment and cursor.
  Insertion/pickup still uses storage 0–35 and atomically rejects excess; it
  does not automatically equip items or consume cursor space.
- Foods are data only; copper/iron armor has `armorSlot` but no defense. No SPEC
  appendix assigns a stack size of 16. The engine supports 16 and tests it without
  inventing such a registry item.
