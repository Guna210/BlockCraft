## What was built

- Implemented `src/engine/rng.ts` with `hashString`, `deriveSeed`, `hash2`, `hash3`, and `PRNG` (using `xoshiro128**`).
- All RNG uses integer math and bitwise operators (`Math.imul`, `>>>`), ensuring cross-environment determinism.
- Implemented `src/gen/noise.ts` with `makeSimplex2D`, `makeSimplex3D`, `makeValueNoise2D`, `makeValueNoise3D`, `makeFbm2D`, `makeFbm3D`, `makeDomainWarp2D`, `makeRidged2D`, and `makeRidged3D`.
- Noise generation is allocation-free per-sample and leverages positional hashing to avoid large permutation tables, while gradients are statically stored in `Float32Array`.
- No `Math.sin`, `Math.pow`, or `Math.random` used in hashing or core generation loops.
- `tests/unit/rng.test.ts` created to ensure determinism and output ranges of hashes and the PRNG.
- `tests/unit/noise.test.ts` created to verify noise correctness (bounds, isotropy, continuity, determinism) and provide benchmark logging.

## Known limitations

- Simplex hashing uses purely functional hash lookups on grid coordinates (`hash2`/`hash3`) scaled to a tiny gradient table to avoid perm arrays entirely, which slightly limits the apparent permutation space to just gradients, but allows for infinite un-tiled deterministic coordinate fields for the voxel engine.

## Notes for dependent tasks

- `makeSimplex2D/3D` returns numbers strictly clamped around `[-1, 1]`.
- Positional hashes (`hash2`, `hash3`) return `[0, 1)`. Use these instead of stateful PRNG when possible to allow chunk meshing and procedural generation to be independently evaluated out-of-order in worker threads.
- Do not use `Math.random()` or `Math.sin()` anywhere near generation.
