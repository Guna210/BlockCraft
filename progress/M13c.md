## CI fix: the World in dictionary mode (commit 7edd8b8)

- Before the fix, verify shard 2 failed on 2553bca: M04b streaming timed out and the shard ran 31.5m. On 4f31479 it went green, but only with 2 flaky tests and a 27.4m run.
- Cause: `new WorldAdapter(world)` redefined `onBlockEdited` on the `World` as an accessor. That turned the `World` into a dictionary-mode object, so every main-thread `World` call got slower, fewer sections were uploaded within the 3 ms per-frame budget, and `uploadsDeferred` never drained.
- Fix: the adapter now gets a two-method view, and the `World` has a `listeners` set for loads, unloads and edits. The spawner skips categories that have no rules.
- Unit probe, one process per mode, time for 1.3M `World` reads:

  | old adapter | 554 ms |
  | fixed | 189 ms |

## What was built

- **Goal-based AI** (`src/entity/ai/goal.ts`, `src/entity/ai/goals/*.ts`): a priority `GoalSelector` with move, look, jump and target flags, and 11 goals:
  - wander, flee, follow food, breed
  - target player, melee, ranged
  - avoid sunlight, climb wall, swell-and-burst, flock
- **Mob runtime** (`src/entity/ai/runtime.ts`): installs AI (−500), navigation (−400), movement (−300) and spawning (−200) systems on an ECS world. It also has:
  - `addMob()` for creature tasks
  - `entityAI()` for the debug API
- **Navigation** (`src/entity/ai/navigation.ts`): a shared round-robin `PathScheduler` with a 2000-node budget, and a per-mob `Navigator` with the re-path policy and a direct-steering fallback.
- **Movement** (`src/entity/ai/movement.ts`): mob physics on the existing collision sweep, with gravity, step-up, jumping, swimming, climbing and flying.
- **Spawning** (`src/entity/spawning.ts`): data rules, hostile, passive and ambient spawning, caps, and despawning.
- **Combat** (`src/gameplay/combat.ts`): `PlayerCombat` with the attack meter, entity raycast before blocks, crit, sweep and feeding. Also `hurtMob` (invulnerability and knockback) and `hurtPlayer` (shield, then armor).
- **Blast** (`src/gameplay/blast.ts`): entity and player damage with distance falloff.
- **HUD** (`src/ui/hud.ts`): a cooldown meter under the crosshair while it recharges.
- **Debug API**: `getEntityAI(id)`.

### Changes to code owned by other tasks

- **`src/world/world.ts`, `src/world/world-manager.ts`:**
  - `listeners` (column loaded, column unloaded, block edited), `notifyColumnLoaded()`, `loadedColumns()` and `unpopulatedColumns`.
  - `WorldManager` announces each applied column (generated or restored), and `removeColumn` announces unloads.
  - Needed for adapter invalidation and first-generation passive spawning.
- **`src/gameplay/tools.ts`:** `ARMOR_DEFENSE` is derived from `armorPoints` in the item JSON, so armor has one source. The values are unchanged.
- **`src/ui/hud.ts`:**
  - The armor bar uses `getTotalArmorDefense`.
  - `HudSnapshot.attackCooldown` and the meter.
- **`src/entity/ecs/entity-types.ts`:** spawners take an optional `{ baby }`, and there is a new `hasEntityType()`.
- **`src/entity/player.ts`:** `isSprinting`, for the sweep rule.
- **`src/gameplay/block-interaction.ts`:**
  - `holdAttack()` stops mining for a press that hit an entity.
  - `cancelUse()` stops a press that fed a mob from also placing a block.
- **`src/engine/player-controller.ts`:** creates `PlayerCombat` and a `MobRuntime` (default spawn rules) per player spawn, runs combat before block interaction, and forwards input.
- **`src/entity/query.ts`, `src/entity/ecs/systems.ts`, `src/gameplay/death-beds.ts`:** `EntityQuery` results carry the mob category, and beds see hostile ECS mobs as hostile.

## Known limitations

- Weapons take no durability loss on hits.
- Players are not knocked back.
- Targeting has no line-of-sight check.
- The populated-column set for first-generation passive spawning is in memory only (persistence is out of scope).
- No spawn rules are registered yet; creature tasks add them.
- Mobs in unloaded columns freeze.

## Notes for dependent tasks

- **Creatures (M13e and later):**
  - Register a type with `registerEntityType(type, (ctx, x, y, z, options) => …)`.
  - Create the entity with `spawnModelEntity`, then `addMob(ctx.ecs, id, {category, speed, foods, flying, climbing, baby: options?.baby, goals: (mob) => [[priority, goal], …]})`.
  - Speeds are in blocks per tick.
  - Add a natural spawn with `registerSpawnRule({type, category, biomes, groupSize, weight})`.
- **Projectiles (M13d):** `RangedAttackGoal` takes `fire(aimPoint, shooterId)`. Damage from a projectile should go through `hurtMob(ecs, id, amount, {ref, pos})` or the runtime's `player().hurt(amount, source, from)`, so invulnerability, knockback, shield and armor apply.
- **Babies (M13e):** `LoveC.baby` marks a baby. Growth is M13e's job; clear the flag when it grows up.
- **Accessing the runtime:**
  - `mobRuntime(ecs)` returns the runtime of an ECS world.
  - `PlayerController.mobs` and `PlayerController.combat` hold the live instances.
  - Only one runtime may be installed per ECS world.
- **Explosions (M14):** `blast()` hurts entities and the player only. M14 adds block removal.
- **Invariant:** never pass the `World` itself to `new WorldAdapter(...)`; use `worldPaths(world)`. The adapter redefines `onBlockEdited` on its argument, which makes the `World` a slow dictionary-mode object (about 3× slower on every call) and stalls streaming. Listen for edits with `world.listeners` instead.
- **Invariant:** every abandoned path search is disposed. `Navigator.stop()` disposes at once, and the scheduler prunes searches of destroyed or dying mobs on the next tick. Goal code that removes a mob mid-tick must use `runtime.remove(id)`, which is deferred to the end of the AI pass.
