## What was built

- A standalone pixel-font world-list overlay using the shared UI kit, with create, select, rename, copy, and confirmed delete actions. Names are trimmed, limited to 1–32 characters, and unique; name clashes show a screen message.
- Atomic all-store IndexedDB delete, rename, and duplicate operations built on the existing save manager and database wrapper.
- Optional PNG thumbnails stored in `WorldRecord` format v1. A visible save requests one rendered frame, which is copied to a 160×90 2D canvas and encoded by a worker. Hidden and exit saves reuse the current thumbnail and issue player/world writes after region flush. The render-loop `drawImage` cost is counted under the `thumbnail` save stretch; when no save is waiting, the loop does no thumbnail canvas work. Worlds without a thumbnail use a code-drawn landscape tile.
- Debug API methods `openWorldList()` and JSON-only `listWorlds()`. The existing debug `createWorld` flow remains unchanged. Removed only the approved DROPS console log from the M17b e2e spec.

## Notes for dependent tasks

- M18a can open the screen through `WorldListScreen.open()`; the debug API's `openWorldList()` is available for tests. The screen is independent of the main menu and can open before a world exists.
- `listWorlds()` returns `{ name, lastPlayed, hasThumbnail }` objects. Rename preserves the current active session under its new name; duplicate copies stored records without changing the source.
