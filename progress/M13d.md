## M04 CI performance follow-up

- `ProjectileRuntime` installs one ECS system when constructed, and the system returns immediately until the first shot. The `VoxelRaycaster` and its hit scratch are created lazily on the first shot, so empty worlds do not query or allocate projectile state each fixed tick.
- Idle HUD snapshots omit the bow charge field, so the existing M13c HUD comparison key remains unchanged unless a bow is charging.
- Historical local one-pass M04b comparison (`--retries=0`): master `203ecbc` stalled at the heap test's post-warm-up gate after 180 s with `uploadsDeferred=84`, and at the RD12 gate after 120 s with `uploadsDeferred=181`. The PR version before the earlier performance changes stalled at the heap test's initial gate after 60 s with `uploadsDeferred=277`, and RD12 after 120 s with `uploadsDeferred=277`.
- The follow-up branch's RD12 gate timed out at 120 s with `uploadsDeferred=276`; individual local ablations were noisy (277–282 deferred). This local comparison was inconclusive. The owner has classified the M04:221/276 retries as a master-level issue being fixed separately in INFRA-stream.

## Changes to existing M13a/M13c integration files

- `src/engine/player-controller.ts`: Added the `bow` and `projectiles` fields; routed `use` input through bow handling before combat and block interaction; ticked bow charge once per fixed tick; cleared bow charge on death, detach, reset, and world teardown. Existing input remains routed to combat and interaction whenever the held item is not a bow or bow handling declines it.
- `src/ui/hud.ts`: Added an optional charge value to the HUD snapshot and draws the existing cooldown meter while a bow is charging. Snapshots and drawing stay unchanged when no bow is charging.
- `src/entity/ecs/pose.ts`: Applies interpolated root pitch only when a transform has pitch. Entities without pitch retain their prior yaw, translation, and pose.
- `src/entity/ecs/systems.ts`: Copies pitch into `previousPitch` only when pitch exists. Ordinary transforms keep their existing object shape and snapshot behavior.
- `src/entity/ecs/components.ts`: Added optional `pitch` and `previousPitch` fields to the transform type for oriented projectiles. Existing entities do not receive either field unless they use pitch.

## Notes for dependent tasks

- M13f can register its own kind with `registerProjectileKind` and fire through `fireProjectile(ecs, { kind, from, dir | aimAt, speed, owner })`. Register its model before its kind. The shared runtime is installed on the player's ECS; the owner value is `PLAYER_TARGET` (0) for the player or the shooter's ECS entity id.
- Mob-fired arrows inherit `pickup: true` from the arrow kind by default. M13f must pass `pickup` explicitly for each shot to choose the intended mob-arrow pickup behavior.
- `aimAt` uses the flatter ballistic solution and falls back to 45° when out of range. M13d does not connect M13c's ranged goal.
