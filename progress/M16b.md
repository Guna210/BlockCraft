## What was built

- Added `src/audio/service.ts` as the runtime audio owner. It lazily creates the sole `AudioContext` on the first pointer or key gesture, records sound IDs before activation in a 64-entry ring, and mixes cached recipe buffers through category gains, a 32-voice priority budget, HRTF inverse-distance panners, rate-limited voxel occlusion, and a shared cave reverb send. Recipe rendering runs through an idle preparation queue; `play()` only starts a prepared buffer. Pickup sounds use an item-collection callback rather than polling the fixed item pool each tick.
- Routed M16a recipes through the runtime bus while keeping offline rendering connected to its `OfflineAudioContext`. Added recipe support for cave cues and Note Blocks, and an M16c sequence renderer that counts a music piece as one voice.
- Wired footsteps, block break/place, pickup, eating, player and creature hurt/death, Blast Charge explosions, rain, delayed thunder, nearby fluid and kiln ambience, piston/button/lever sounds, bow draw/release, arrow impacts, and Note Blocks. Creature idle calls and cave/music schedules use seeded randomness.
- Added `getAudioStats()` in `src/debug/api/audio-stats.ts` and registered it as a separate debug API module. Exposed registered creature type IDs for complete voice-recipe coverage.
- Routed each M14 explosion through the audio service's enqueue-only path: inside an explosion step it records the sound ID and writes scalar position/priority data into preallocated scratch arrays. Coalescing, pending-playback creation, and Web Audio node work run after the step. Pending explosions are keyed by ID and position, and recent-playback records are mutated rather than reallocated. Occlusion phases are batched once per four ticks while retaining the per-voice rate limit. Added the requested M12 rain assertion.

## Notes for dependent tasks

- Game playback goes through `sound.play(id, { pos?, priority? })` in `src/audio/service.ts`. Audio recipe IDs remain in `src/audio/recipes/`; M14 calls `entity.explosion` through `src/gameplay/explosions.ts`.
- `window.__blockcraft.getAudioStats()` returns `{ contextState, activeVoices, lastSounds }`; the sound history is chronological and bounded to the latest 64 IDs.
- Existing `masterVolume`, `musicVolume`, `effectsVolume`, and `ambientVolume` settings are read live. No audio settings UI was added.
