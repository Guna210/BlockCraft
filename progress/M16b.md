## What was built

- Added `src/audio/service.ts` as the runtime audio owner. It lazily creates the sole `AudioContext` on the first pointer or key gesture, records sound IDs before activation in a 64-entry ring, and mixes recipe output through category gains, a 32-voice priority budget, HRTF inverse-distance panners, rate-limited voxel occlusion, and a shared cave reverb send.
- Routed M16a recipes through the runtime bus while keeping offline rendering connected to its `OfflineAudioContext`. Added recipe support for cave cues and Note Blocks, and an M16c sequence renderer that counts a music piece as one voice.
- Wired footsteps, block break/place, pickup, eating, player and creature hurt/death, Blast Charge explosions, rain, delayed thunder, nearby fluid and kiln ambience, piston/button/lever sounds, bow draw/release, arrow impacts, and Note Blocks. Creature idle calls and cave/music schedules use seeded randomness.
- Added `getAudioStats()` in `src/debug/api/audio-stats.ts` and registered it as a separate debug API module.
- Replaced M14’s private explosion synthesizer with the central service and added the requested M12 rain assertion.

## Notes for dependent tasks

- Game playback goes through `sound.play(id, { pos?, priority? })` in `src/audio/service.ts`. Audio recipe IDs remain in `src/audio/recipes/`; M14 calls `entity.explosion` through `src/gameplay/explosions.ts`.
- `window.__blockcraft.getAudioStats()` returns `{ contextState, activeVoices, lastSounds }`; the sound history is chronological and bounded to the latest 64 IDs.
- Existing `masterVolume`, `musicVolume`, `effectsVolume`, and `ambientVolume` settings are read live. No audio settings UI was added.
