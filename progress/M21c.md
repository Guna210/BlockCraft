## Known limitations

- Container/crafting windows are expressly deferred. Window zero covers the owned inventory/cursor only.
- The pre-existing protocol does not replicate player vital/mode/death snapshots. Multiplayer does not invent local survival state; extending those HUD/death states requires a subsequent protocol change.

## Notes for dependent tasks

### M21b-fix — container windows over the network

- `src/game/net/inventory.ts` queues window-zero intent against server revisions; snapshots own slot/cursor values. Extend the protocol and server validation for container ownership, reach, revisions, crafting and close behavior.
- `UiManager.inventoryOnly` prevents local container/crafting mutations during a remote session. Replace the relevant guards when real server windows exist; do not open local chest/kiln/workbench implementations on remote terrain.
- Preserve ordered input-before-BlockAction handling, continuous authoritative player physics, portal sequence continuity and fresh destination entity baselines. Send one PlayerCorrection after every server tick: the client authoritative movement checkpoint advances once per message, so these messages must not be coalesced. Network block edits use BlockAction exclusively; do not re-enable implicit held-input mining/placing when adding container actions.

### M22 — culling and batching

- Remote terrain uses the same Streamer, worker lighting/meshing and ChunkRenderer, but its data comes exclusively from the server. Missing/perimeter/LOD terrain must never be generated from the seed or saved locally. Server view distance bounds received terrain.
- Remote players are rendered through a session-owned wrapper of PlayerModelRenderer inside the entity pass; they are separate from the ECS used by other replicated entities. Do not cull them using only local-player or ECS assumptions.
- Preserve the 100 ms sampled pose when batching models and projecting name tags. Update labels after camera changes and retain behind-camera hiding. Restore renderer callbacks and remove labels on exit/travel.
- Multiplayer timers are independent of animation frames and are removed on disconnect/exit. Keep networking work off the single-player tick/frame path and keep World/Player free of networking fields.
