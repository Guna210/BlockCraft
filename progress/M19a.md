## What was built

- A biome-filtered seeded placement grid with region queries and nearest-start lookup, configured for `wayfarer_hamlet`.
- Breadth-first connector jigsaw assembly with weighted pools, four rotations, depth and piece limits, and non-overlapping piece bounds. Each layout seed includes its start chunk.
- Pure terrain adaptation for foundations and stilt supports, plus a `structures` pipeline stage after features. The default pipeline registers no templates and writes no structure blocks.
- A separate chest-loot loader and deterministic roller, plus optional Keen, Sturdy, and Swift stack affixes through inventory operations, tool stats, tooltips, and the existing v1 inventory serializer. M19a stores no chest content.

## Affix carry-through

- `src/ui/ui-manager.ts`: external inventory, chest, and kiln stacks retain validated affixes through clicks and quick moves. `sameItemStackKind` compares item ID, damage, and affix so unlike variants do not merge. Crafting, chest, and kiln tooltips use affixed names.
- `src/ui/kiln-screen.ts`: kiln stack affixes are validated before display; tooltips use the affix name prefix, and durability bars use the full stack so Sturdy tools show their increased maximum durability.
- `src/ui/inventory-screen.ts`: inventory durability bars use the full stack, and hovered item names use the affix prefix.
- `src/gameplay/crafting-session.ts`: crafting slot snapshots carry damage and affix data so item variants survive crafting-grid operations.
- `src/gameplay/block-interaction.ts`: mining speed uses the held stack, including Swift. The computed tool and speed are cached until the held ID or affix changes, avoiding tool-object creation in steady-state ticks.
- `src/engine/player-controller.ts`: durability checks use the held stack, applying Sturdy's increased maximum durability.

## Known limitations

- No structure templates are registered in M19a. M19b and M19c supply them through the pipeline registration interface.
- `ItemEntity` drops the affix on drop and pickup, including when a chest breaks; M19b owns that carry-through.
- The structures stage uses `sampleTerrainTopY`, which ignores M18a's flat and amplified terrain variants. M19b decides flat-world behavior.
- The local e2e container has no bundled Chromium executable, so the requested browser specs could not launch. GitHub PR CI is the full-verification evidence.

## Notes for dependent tasks

- `createDefaultPipeline(registrations)` accepts structure registrations; each pipeline instance owns its bounded start-assembly cache. Keep structure generation deterministic from the world seed and start inputs.
- Placement configs live in `data/structures/placement.json`; `createPlacementGrid` supports candidate, bounds, and nearest queries.
- Chest tables use `data/loot/chests/*.json` and `src/gameplay/chest-loot.ts`; M19b adds Hamlet loot. Block-drop tables remain in the direct `data/loot/*.json` folder.
- Affixes are optional `ItemStack.affix` values. The inventory format remains version 1, and `getAttackDamage`, `getMiningSpeed`, and `getToolDurability` accept a stack input.
