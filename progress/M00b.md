## Known limitations

- The `harness-guard.yml` GitHub workflow cannot be run automatically in this local VM environment since it relies on `pull_request_target` event payload and GitHub API interactions. However, it can be easily validated via a throwaway PR after merge to ensure that altering protected files correctly blocks PR checks without the `harness-change` label.

## Notes for dependent tasks

- Moving forward, `tests/harness/`, `.github/workflows/`, `playwright.config.*`, `scripts/verify.*` and `scripts/lint-placeholders.*` are effectively read-only. Avoid modifying them unless explicitly required by your task (at which point you must request the `harness-change` label from the owner on the PR).
- Any further E2E specs should import the custom `test` and `expect` from `../harness/fixture` to automatically run tests enclosed with error checks and the debug API `ready` promise wait.
- E2E tests are able to save screenshots to `artifacts/` via the exposed `assertAndSaveScreenshot` fixture parameter. Ensure screenshots are captured before running assertions on them to allow inspection in `artifacts/` on test failure.
