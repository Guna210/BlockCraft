## What was built

- Implemented `src/engine/input.ts` to manage user input state and keybinds for a fixed set of actions. Includes tests for rebinding and programmatically setting input states.
- Implemented `src/render/camera.ts` with a 3D perspective camera (FOV 70, aspect ratio). The camera implements WASD + mouse free-fly controls using the `gl-matrix` math library and the input engine. Contains unit tests validating correct projection and directional math relative to yaw and pitch.
- Implemented `src/render/gl.ts` to abstract WebGL2 state. Contains wrapper functions for creating and disposing buffers, shaders, VAOs, and textures. Includes resource counting to prevent leaks. Includes a shader compile error log formatter to print actual file and line context for shaders. Contains tests checking these behaviors and resource counting using a mocked `WebGL2RenderingContext`.
- Added debug-mode GL error loop tracking. When the game URL contains `?debug=1`, the GL wrapper's draw calls continuously query `gl.getError()` until no more errors remain, and logs them to `getRenderStats().glErrors` via callback.
- Added `gl-matrix` as a project runtime dependency, which is the only allowed external runtime rendering library in `SPEC.md`.

## Decisions (links to decisions/ files)

- Decided to instantiate the `GLWrapper` in `src/main.ts` but limit modifications to preserving the existing M00 sky-blue clearing functionality. Full scene implementation using the wrapper is left to M01c.
- The ?debug=1 parameter logic is executed once on startup to instantiate `GLWrapper` so it does not tightly couple to the `debug` api or the DOM during the tight render loop.

## Known limitations

- The camera and input engines are fully tested in isolation but are not actively driving a 3D view in `main.ts` yet since the test scene is not built until M01c.
- Actions cannot currently be unbound completely back to empty keys via UI (no UI exists yet), but the underlying code supports unbinding.

## Notes for dependent tasks

- Ensure that any future WebGL objects (buffers, VAOs, textures) are built using the new `GLWrapper` inside `src/render/gl.ts`. If you skip using the wrapper, your resources will not be tracked or count toward leak checks in unit testing.
- The `Camera` sets pitch limit just shy of Math.PI / 2 radians (90 degrees) to avoid gimbal lock/screen flipping. If different vertical camera constraints are needed, adjust the clamping logic in `camera.ts`.
- M01b can begin working on the textures knowing the webgl primitives can be utilized smoothly once M01c joins the implementations together.
