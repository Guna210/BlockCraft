## What was built

Worker-side rectangular lighting, per-channel block light, light skirts, smooth per-vertex sampling, AO and diagonal selection, shader interpolation and brightness controls, and a procedural standing torch. Light batches choose a contiguous ready strip along either horizontal axis. Upload queues also follow distance priority and release mesh backpressure immediately when uploads drain.

Corner sampling shares a nine-cell stencil between the four corners. Worker-computed metadata selects a smaller shader when RGB is uniformly zero; the full RGB shader remains available for every emitting section. Face normals are flat because each quad has one normal. The latest owner-requested shader revision evaluates brightness, tint, AO and face shading per vertex, then multiplies their interpolated values in the fragment stage.

Debug-light changes draw immediately, including when a caller holds the normal frame loop. Wireframe outline buffers are uploaded lazily on first use and freed with their mesh; normal streaming avoids their allocation, index construction and upload.

## Pipeline fixes and investigation

An early full run had only the same blank mid-flight failure as master, but throughput and visibility were below the owner's targets. Instrumentation found large worker-result delivery delays rather than expensive mesh computation. A native thread sample showed GPU work dominating the two-core quota. Experiments with reply coalescing, mesh concurrency alone and alternate shaders did not meet all targets and were removed.

Retained changes bound posted generation to eight columns per worker, mesh to 32 sections per background worker while preserving foreground reserve (single-worker pools remain sequential), and light to four posted batches computed serially on one worker. Distance priorities and independent stale-column rejection remain. The earlier terrain-fence experiment let update callbacks continue without drawing, but was rejected and removed. The existing per-frame GL error drain remains unchanged; every terrain callback now renders. An earlier interpretation of rounded FPS 0 as frozen drawing was corrected with actual submission counters.

Main-thread light snapshots copy section by section in 1 ms tasks. Column commits alternate with generation application and mesh preparation in the existing 3 ms pump budget; serial validity is checked immediately before each commit. Initial region commits also yield. New tests cover copy task separation and an edit between commit slices. The gated pipeline full run exposed four cadence/stale-view failures; source fixes passed seven targeted checks and the superseded gated full run passed every test. No legacy assertion was changed.

- M12 should animate the renderer's sky-brightness setter; its default is full day brightness.
- Lamp emission 15 and glowcap emission 9 remain future registry work; no placeholder blocks were added.
- M22a must account for the measured +96.8864% spawn-triangle cost of merging only uniformly lit/AO faces, while preserving the strict merge rule. Do not relax the merge rule.
- `src/mesh/vertex.ts` defines packing and shared decoding. Word 0's former scalar block-light field now means R; word 1 carries G/B along with the smaller tile/UV fields.
- Light skirts are stored per column. A mesh worker uses stored neighbour light when lit and the exact skirt otherwise. Initial region lighting commits the inner square; its outer generated ring supplies the block border and receives its own skirt when streamed meshing wants it.
- Edits apply RGB/scalar incremental BFS immediately, then refresh affected columns' worker-computed skirts. Nearby snapshots also depend on the block border: an unlit border edit invalidates them even when guarded BFS records no touched sections. Invalidations are deduplicated and each affected snapshot is rejected independently; other columns in the batch still commit.
- Light storage omits zero sections and shares the immutable sky sentinel, cloning it on an edit. Removal frees scalar, RGB and skirt data with the column.
- Completed stage counters count columns, including mesh attempts needing no section jobs. Mesh/upload cancellation counters retain the existing job units; a running section and a queued column are each a cancellable job.
