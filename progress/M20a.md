## What was built

- `src/world/dimension.ts`: `DimensionId`, 1:4 scaling and the per-dimension definitions
  (pipeline, portal y range and platform block).
- The generation worker and pool carry the dimension, with one pipeline per dimension.
- The `portal` block (axis x|z, ids 833/834) with its item, empty loot table, texture and icon,
  and a violet light tint.
- The M20b wiring:
  - the Hollowdeep pipeline in the worker and the main-thread fallback;
  - per-dimension biome lists for the worker, the receiver and restored saves;
  - `HOLLOWDEEP_ENVIRONMENT`: fog colour and range, no sky light, no sky, clouds or weather, spore
    particles (`src/render/spores.ts`), and lava flow rate. It reverts on return.
- `src/world/portals.ts`: frame detection, `PortalIndex`, `PortalGuard` (collapse on frame
  break), the link search, the seeded safe-spot search with platform fallback, and the
  `PortalTravel` state machine.
- `src/render/portal.ts`: the animated swirl surface pass and the `WarpOverlay` screen effect.
- `WorldManager`:
  - per-dimension portal indices;
  - `changeDimension()` (save, tear down, a new `World` on the other dimension's store, stream,
    link or build a portal, place the player);
  - the Ember Flint use;
  - the portal tick and draws.
- `SaveManager`:
  - `load(name, dimensionOf)` opens the player's dimension;
  - `loadDimension()` and `switchDimension()`;
  - the portal index is saved in each dimension's entities record.
- `PlayerController`: `suspended` (it skips ticks while the dimension swaps) and an `onTick` hook.
- Debug API `src/debug/api/dimension.ts`: `getDimension`, `travelTo`, `waitForTravel`,
  `getPortals` and `getPortalTravel`.

## Changes to other tasks' files

Both test edits were approved by the owner through the orchestrator (decisions §8):

- `tests/unit/m10a-reachability.test.ts`: added a `portal` exemption, because the portal is lit,
  not crafted or mined, and drops nothing. This is the same pattern M19c used for its blocks.
- `tests/unit/m19c-structures.test.ts`: now identical to master's version (M20b removed the global
  max-id assertion and the unused `ids` local), so this PR no longer changes it.
- `src/workers/gen.worker.ts`, `gen-worker-pool.ts`, `save-manager.ts`, `world-store.ts`,
  `main.ts`, `light-curve.ts` and `textures/index.ts`: minimal hooks, each described above. The
  worker also encodes biomes through the active dimension's biome list.
- `src/engine/player-controller.ts`: merged with M16b. Both the sound tick and the `onTick` hook
  run each tick, and `reset()` clears `suspended` as well as M16b's mechanics listeners.
- `src/render/chunk-renderer.ts`: an optional `u_dimensionFog` uniform (set through
  `setAtmosphere`) replaces the sky fog colour while it is set.
- `src/world/fluids.ts`: `FluidSimulation.lavaTickDelay` (default `LAVA_TICK_DELAY`), so the
  Hollowdeep can set its own lava flow rate.
- `src/world/world-manager.ts`: restored columns re-map their biome indices to the active
  dimension's list, because the column format decodes with the Overworld's list.

## Known limitations

- Unnamed (unsaved) worlds don't keep the inactive dimension. It regenerates, and index entries
  whose portals are gone are dropped when their column loads.
- The warp is a screen overlay only (no FOV change).
- The portal block appears in the creative inventory, like other technical blocks.
- In the Hollowdeep, entity, player-model and drop shaders still use the sky's fog colour (only
  terrain uses the cavern fog). There are no Hollowdeep creatures yet (M20c).
- Natural spawn rules with an empty biome list still apply in the Hollowdeep. Hollowdeep creatures
  and their rules are M20c's.
- Arrival spots count any solid full cube as ground, so a portal can stand on a glowcap canopy.

## Notes for dependent tasks

    `WorldManager.drawTerrain` reading `HOLLOWDEEP_ENVIRONMENT`).
  - `debug.travelTo('hollowdeep', x, y, z)` moves the player without a portal. It returns the
    arrival portal and resolves once the terrain there is meshed.

- `WorldManager.dimension` is the active dimension. Code that keeps per-world state must reset it
  on travel, which tears down the World instance the way loading a world does.
