## What was built

- **Tags & Recipes (`data/tags/items.json`, `data/recipes/*.json`)**:
  - Defined 6 item tags in `data/tags/items.json` (`any_planks`, `any_log`, `any_sand`, `any_mushroom`, `any_wood_slab`, `any_leaves`).
  - Added 106 recipes across 9 category files: `wood.json` (13), `slabs.json` (9), `tools.json` (30), `armor.json` (8), `light.json` (3), `terrain.json` (14), `materials.json` (8), `food.json` (4), and `smelting.json` (17).
- **Blocks, Items, Loot & Textures**:
  - Added craftable simple blocks (`rainwood_planks`, `acacia_planks`, `coarse_dirt`, `mud`, `lumite_block`) with wrap-seamless procedural textures and declared palettes, plus `lumite_block` light color `[0.45, 0.85, 1]` in `src/render/light-curve.ts`.
  - Added 7 craftable slabs (`oak_slab`, `birch_slab`, `pine_slab`, `rainwood_slab`, `acacia_slab`, `cobblestone_slab`, `mossy_cobblestone_slab`) with `half: bottom | top` states and append-only state IDs `118..136` in `data/block-state-ids.json`.
  - Added `gold_ingot` and `arrow` to `data/items/materials.json`.
  - Added `data/loot/ores.json` (`coal_ore` → `coal`, `copper_ore` → `raw_copper`, `iron_ore` → `raw_iron`, `gold_ore` → `raw_gold`, `lumite_ore` → `lumite_shard`, `skyshard_ore` → `skyshard_crystal`) and updated `gravel`, `tall_grass`, and leaf loot tables (`data/loot/terrain.json`, `data/loot/vegetation.json`, `data/loot/wood.json`, `data/loot/wood-extra.json`) so survival progression is reachable from worldgen blocks.
- **Crafting & Smelting Registries (`src/gameplay/crafting.ts`, `src/gameplay/smelting.ts`)**:
  - `CraftingRegistry` builds shaped (trimmed bounding-box + horizontal mirror) and shapeless lookup maps once at startup, expands tag ingredients, verifies zero recipe ambiguity across all concrete candidate grids, and exposes pure `match(grid)` and `maxCrafts(grid)` for 2×2 and 3×3 grids.
  - `SmeltingRegistry` loads `data/recipes/smelting.json`, validates all inputs/outputs against `itemRegistry`, and exposes `getByInput(itemId)` and `isFuel(itemId)`.
- **Tools & Armor Query API (`src/gameplay/tools.ts`)**:
  - Exposes `TOOL_TIERS` (`wood`, `stone`, `copper`, `iron`, `skyshard`), `ARMOR_DEFENSE` (Copper = 10 total, Iron = 15 total), `getMiningTool`, `getMiningSpeed`, `getHarvestLevel`, `getToolDurability`, `getAttackDamage`, `getArmorDefense`, and `getTotalArmorDefense`.
- **Block-Entity Framework (`src/world/block-entities.ts`, `src/world/world.ts`)**:
  - `BlockEntityRegistry` registers block-entity types with plain-JSON state (`create()` and optional `tick()`).
  - `BlockEntityManager` wired into `World` creates block entities when placed via `setBlockStateId`, removes them when broken/replaced or when their column unloads via `removeColumn`, and ticks them only in loaded chunks via `World.ticks` (`BLOCK_ENTITY_TICK_TYPE = 'block_entity'`).

## Known limitations

- Stairs, fences, doors, and trapdoors are not registered in M10a because their non-cube geometry belongs to later tasks.
- Smelting is data-only (`data/recipes/smelting.json` and `src/gameplay/smelting.ts`); the kiln block entity, workbench 3×3 UI, chest block entity, tool durability wear, and harvest-drop enforcement belong to M10b and M10c.
- `MILESTONE=M10 npm run verify:quick` reports `e2e: ✗ failed` only because `tests/e2e/m10*.spec.ts` has no files yet (M10a is unit-only; M10b/M10c add the M10 Playwright specs).

## Notes for dependent tasks

- **Crafting API (`src/gameplay/crafting.ts`)**:
  - Import `crafting` singleton or `CraftingRegistry`.
  - `crafting.match(grid)` accepts a 2×2 or 3×3 2D array of `string | null | undefined` or `{ itemId: string | null; count: number } | null` slots and returns the matching `CraftingRecipe | null` (automatically checking `gridSize <= grid.length` so 3×3-only recipes never match in a 2×2 grid).
  - `crafting.maxCrafts(grid)` returns the maximum number of crafts supported by current stack counts in the grid.
- **Smelting API (`src/gameplay/smelting.ts`)**:
  - Import `smelting` singleton (`smelting.getByInput(itemId)`, `smelting.isFuel(itemId)`).
- **Tools & Armor API (`src/gameplay/tools.ts`)**:
  - Import `TOOL_TIERS`, `ARMOR_DEFENSE`, `getMiningTool`, `getMiningSpeed`, `getHarvestLevel`, `getToolDurability`, `getAttackDamage`, `getArmorDefense`, `getTotalArmorDefense`.
  - Keep `data/items/armor.json` free of `defense`/`durability` fields so `tests/unit/m09a-registry.test.ts` continues to pass; query armor defense through `getArmorDefense(itemId)`.
- **Block-Entity API (`src/world/block-entities.ts` & `src/world/world.ts`)**:
  - Register block-entity types with `blockEntityRegistry.register({ blockId, tickInterval?, create: () => ({ ... }), tick?: (entity, world) => { ... } })`.
  - Read or mutate live plain-JSON state via `world.getBlockEntity(x, y, z)` or `world.blockEntities.get(x, y, z)`.
