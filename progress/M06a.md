## What was built

A bounded 20 TPS accumulator and reusable player physics, with a controller that interpolates the existing camera, keyboard/mouse action wiring and the SPEC player debug API. Collision queries use existing world state accessors and precomputed numeric shape/fluid/hay tables. Health/fall damage, creative flight and conservative terrain readiness are part of the same tick function. No worker capacity, draw cadence, harness, prior-milestone test or protected owner file changes.

Hay is registered through the existing JSON glob, with deterministic five-color top/side generators. A minimal stone slab reuses the existing stone tile to supply genuine half-height geometry for the step and gap tests. Its two-word mesh uses one formerly spare bit for half-Y and the existing model bucket; integer vertex fields and cube encodings are unchanged.

## Notes for dependent tasks

- `src/engine/loop.ts`: fixed tick loop, five-tick catch-up cap, manual paused ticks.
- `src/entity/player.ts`: double-precision feet position/velocity, previous tick position, health, mode, sneak height/eye, flight and input edges.
- `src/entity/physics.ts`: cached state shapes; swept per-axis collision, support, fluids/hay and shortest-axis ejection. Stone slabs have top/bottom half states; non-cube plants/torch and fluids do not block players.
- `src/engine/player-controller.ts`: live input and interpolated camera. The legacy initial camera view is detached while the player stands at its physical spawn; first control attaches that spawn. Direct external camera writes detach the player indefinitely; teleport/input/look reattach. On input/look, feet adopt current camera position minus eye height. Debug teleport coordinates are feet, not eyes. Legacy test cameras and the flight helper remain unchanged.
- `src/debug/api/player.ts`: JSON player snapshot, teleport, input, look, pause/resume/tick, mode. `tick(n)` runs synchronously while paused, then resolves; it does not wait for workers. Use `waitForTerrain` after edits/before advancing into unloaded terrain.
- `src/world/world-manager.ts`: new worlds spawn using findSpawnPoint, resets clear the old player, and the controller queries the streamer's meshed/uploaded phase for all footprint columns. Detached legacy cameras keep driving streaming.
- M06b should extend these interfaces for water movement, climbing, third-person and camera effects. Hunger/saturation/air are initialized state; M11 supplies their survival simulation. No later-task methods or placeholder systems were added.
- Other-task source touched only for M06a integration: main loop; input action notifications; core API types/index and existing look routing; world lifecycle spawn/reset; block model types, slab model emission, shared vertex decoder and shader half-Y decoding; procedural texture registration. No existing tests were edited.
