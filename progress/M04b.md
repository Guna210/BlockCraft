## What was built

- **`src/render/dither.ts`** — the 4×4 Bayer table; the same table feeds the fragment shader as a GLSL array (`bayerGlsl()`).
- **`src/render/column-fade.ts`** — `FADE_IN_MS = 400`, `fadeAmount`, and `ColumnFades`: a fade starts at the first section upload of a column that has no section meshes on the GPU, and ends when its last section mesh is freed.
- **`src/render/chunk-renderer.ts`** — `u_fade` uniform and the dither discard at the top of the fragment shader (before the wireframe early return); one `uniform1f` per column per pass; `uploadSectionMesh(…, fadeFromMs)`; the wireframe overlay now loops over visible columns to apply their fades; `fadingColumns(nowMs)`.
- **`src/world/mesh-attempts.ts`** — `MeshAttempts`, the store of each open attempt's uploaded sections. An entry exists only while an attempt is open.
- **`src/world/streamer.ts`** — `StreamerHost.abandonMeshAttempt(cx, cz)`, called from `discardAttempt` when the column is `meshing`; `requestPending` getter.
- **`src/world/world-manager.ts`** — the streamer host uses `MeshAttempts`; `abandon` on `freeMesh` and `freeData`; the store is cleared with the GPU meshes in `loadInitialWorld` and `resetWorldToEmpty`; `uploadSection` passes no fade start while `createWorld` or a region request is pending; `getStreamingStats()` returns `WorldStreamingStats` (adds `columnsFading`).
- **`src/debug/api/core.ts`, `src/debug/api/streaming.ts`** — type updates only (the one new field is `columnsFading`).
- **`tests/e2e/m04.spec.ts`** — the three M04b tests and helpers (`heapUsedAfterGc`, `waitForFadesDone`, `skyShare`, `frames`).

Existing tests changed: `tests/unit/streamer.test.ts`'s `FakeHost` gains `abandonMeshAttempt` (it records calls and mirrors the world manager's attempt store). No assertion was changed or removed.

## Known limitations

- **`m04-fast-flight.png` shows loading gaps and the loaded-area edge.** Probe on this branch (a temporary spec, removed; same pose at 500 blocks along the flight): right after the flight 1.1–1.4 % of the frame was sky-coloured; after streaming went idle (`columnsFading` 0, no queued work) 0.60 %; with render distance 12 set from the same pose and streaming idle, 0.07 %. So about half of the gap was chunks still loading, and most of what remained was the RD 8 edge. Both are expected at this speed on SwiftShader (the M04a notes give about 1.3 frames per second at RD 8). The gaps are wider than "a few chunks at the far edge", so the Visual Review item is not met as written. The owner decides whether to accept this frame, retake it when streaming keeps up (M22a), or change the checklist.
- **Horizon hole check covers the centre half of the lower third only.** The frame is 16:9 with a 70° vertical FOV, so its outer lower corners look at the far corners of the RD 12 square. There the sky is correct (the edge of the loaded area): 11.2 % of the left quarter at this pose. The check cannot prove that the far edge is correct, only that there are no holes in the centre. The top tenth must be more than half sky; that holds (100 %).
- **The fade is rarely visible under SwiftShader.** A frame takes about 0.75 s here, so a 400 ms fade usually ends before the next frame. The e2e flight reports `columnsFading` above zero (23–45 in the runs above), which shows fades happen; no e2e test checks a pixel mid-fade. The dither itself is covered only by unit tests of the table and the shader source string.
- **Heap resolution.** `usedJSHeapSize` moves in 100 KB steps here, so a 15 % limit is checked with a resolution of about 0.5 %. The test would miss a leak smaller than that per run; it would catch one that grows the heap by more than 15 %.
- **A column whose generation failed three times still blocks its neighbours** (the known M04a limitation). No test here hit it.
- **Mesh failures are still silent** (M04a limitation).
- **Re-mesh of a column whose section meshes were all freed by a stale completion** fades again: `finishIfDone`'s stale branch frees the column's meshes, so the column disappears and fades back in. This is outside decision 2 as written (it is neither invalidate nor endMeshAttempt), and I did not change it.

## Notes for dependent tasks

- **M05b** (lighting): a column's fade starts at its first section upload (`uploadSection` in `world-manager.ts`). If M05b changes a column's light after that upload, the change shows during the fade, as it does for any mesh update. Nothing in M04b depends on the light data.
- **M22a** (culling and batching): `ChunkRenderer.render()` sets `u_fade` per column in each pass. A batched draw must keep the fade per column (one uniform per column or per batch of columns with equal fade).
- **Debug API:** `getStreamingStats()` returns `WorldStreamingStats` (`columnsFading` is time-based, read at the call). A test that waits for it to reach zero should still wait two frames before a screenshot.
- **Attempts:** `StreamerHost.abandonMeshAttempt` must be implemented by any new host; the streamer calls it from `discardAttempt` only while a column is `meshing`.
- **Heap test:** `window.gc` needs `--js-flags=--expose-gc`, already in `playwright.config.ts`. The test throws if it is missing.
