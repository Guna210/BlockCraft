## What was built

`VoxelRaycaster` uses reusable result/scratch objects and cached state AABBs. Shared slab constants keep physical and target shapes consistent. `BlockInteraction` extends the fixed player ticks with mining, placement and creative picking. A player held state supplies blocks while no inventory exists. Existing mouse/debug actions drive the same simulation.

Ten deterministic four-color procedural crack stages draw through a static GPU texture array; a static dark wire outline encloses the target hitbox. Both draw after terrain, before underwater post tint, with depth offset.

Wall torches use a new category JSON entry with four states and two tilted crossed sprites through the existing model pass. Packed reserved normals identify the sprites; shader and CPU decoder reconstruct the same geometry. Their texture and light match floor torches.

All interaction edits use existing world edit and incremental lighting. Foreground section mesh jobs use the existing worker pool and reserved edit capacity; boundary sections also update. Uploads share the existing 3 ms budget; bulk relight/re-mesh remains intact. Per-section serials/world epochs reject stale edit jobs.

Shared-quad normalization also retains all emitted front/back indexed quads; ordinary sections use the original shader operations, with wall-torch decoding compiled only into a content-selected variant.

Other-task source touched only as M07a requires: player/controller/input integration; shared physics slab constants and non-solid wall-torch classification; block model types, packing decoder/GLSL and model meshing; shared-quad normalization; WorldManager render/edit integration; debug API types and single registration import; floor-torch RGB lighting reuse; terrain and log tool metadata. Protected owner files, harness, prior milestone tests, worker sizes, draw cadence and `src/entity/ai/` are untouched.

## Notes for dependent tasks

- `src/world/raycast.ts`: reusable `VoxelRaycaster.cast(eyeX, eyeY, eyeZ, dirX, dirY, dirZ, reach, out)`; `createRayHit()` allocates only initialization/debug results. Inside-box rays report the outgoing face.
- `src/world/block-shapes.ts`: per-state boxes, replaceability, slab constants and wall-facing convention. Air/water/lava have no target box. Plants replace; torches, climbers and fluids do not.
- `src/gameplay/mining.ts`: pure Appendix A.1 function with type/tier/speed tool parameter; `BlockInteraction.tool` is bare hand in M07a.
- `src/gameplay/block-interaction.ts`: controller-owned fixed-tick target/progress/placement; M07b supplies selected inventory block/tool and listens at completed edit for drops/particles. Numeric `Player.heldBlock` is the temporary source while no slots exist.
- `src/debug/api/raycast.ts`: `raycast()` plus documented `setHeldBlock(id,state?)` and `getInteraction()` diagnostics. Debug methods return ordinary JSON; invalid held states reject. Use action names `attack`, `use`, `pick`, paused `tick()` and `look()`.
- `src/mesh/wall-torch.ts`: model kinds 8–11, packed normals 6/7, tint bits facing north/south/east/west. Other packed fields retain their layout. Four states use the existing torch palette/texture; wall-torch pick retains the targeted block's default state.
- `WorldManager.requestInteractionMesh`: called after world edits for prompt foreground mesh work; edit snapshots coalesce per section, epoch-check, and upload ahead of bulk work within the shared budget. Diagnostics record actual terrain frames and uploads.
