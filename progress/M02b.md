## Culling Rules Implemented

1. **Opaque Neighbor Culling:** A face is hidden when its neighbor is a full opaque cube (`isOpaqueCube === 1`).
2. **Translucent Type Culling:** Two adjacent translucent blocks of the same type (`water`–`water`, `glass`–`glass`, matching `translucentGroup` ID) hide their shared faces. Adjacent translucent blocks of differing types (e.g. `water`–`glass`) keep their shared faces.
3. **Leaves Rule:** Leaves are cutout blocks (`renderLayer === 'cutout'`) and keep faces between each other.
4. **Fast Paths:**
   - **All-Air Section:** If all blocks in the 16³ core are state `0` (air), returns empty bucket data instantly without scanning slices.
   - **All-Opaque Section:** If all blocks in the 16³ core AND all 6 outer boundary shell blocks in the 18³ padded copy are full opaque cubes, returns empty bucket data instantly without scanning slices.

## 3D Checkerboard Face Count Derivation

- A 16×16×16 core section contains $16^3 = 4,096$ total block positions.
- In a 3D checkerboard where a position $(x, y, z) \in [0..15]^3$ is solid stone if $(x + y + z) \bmod 2 = 0$ and air otherwise, exactly $4,096 / 2 = 2,048$ positions contain solid stone blocks.
- Every solid stone block has 6 orthogonal neighbors. Because every neighbor has coordinate sum with opposite parity (odd), all 6 neighbors are air blocks.
- Therefore, every solid block has all 6 faces exposed (none culled by neighbors).
- Total exposed faces = $2,048 \text{ blocks} \times 6 \text{ faces/block} = 12,288 \text{ faces}$.
- Since no two solid blocks share an edge or face on the same plane, no 2D greedy merging occurs.
- Total quads produced = $12,288 \text{ quads}$.

## What was built

- `decisions/M02b-vertex-format.md`: Recorded bit layout for packed 2×uint32 vertex format (position within section, normal index, tile index, quad-local UVs in block units, default lighting/AO constants), uint32 index array buffer format, and merge key rules.
- `src/world/padded.ts`: Implemented `buildPaddedSection(world, sx, sy, sz, target)` to extract an 18×18×18 `Uint16Array` of block-state IDs from `World` with 1 block of padding on all 6 faces.
- `src/mesh/greedy.ts`:
  - `buildMeshLookupTables(registry, tileResolver)`: Builds flat typed arrays (`isOpaqueCube`, `renderLayer`, `translucentGroup`, `logAxis`, `tileIndices`) without DOM, WebGL, or `World` dependencies.
  - `shouldCullFace(selfState, neighborState, tables)`: Implements face culling rules.
  - `greedyMesh(paddedSection, tables)`: Pure worker-ready greedy mesher using module-level pre-allocated scratch buffers (`SCRATCH_MASK`, `SCRATCH_VISITED`, `opaqueScratch`, `cutoutScratch`, `translucentScratch` sized for up to 24,576 quads) for zero inner-loop allocations.
  - Handles rotated quad-local UV block units for $X$-axis and $Z$-axis log side faces.
  - Returns separate typed array bucket outputs (`opaque`, `cutout`, `translucent`) with `vertices` (`Uint32Array`), `indices` (`Uint32Array`), `vertexCount`, and `quadCount`.
- `tests/unit/greedy.test.ts`: Comprehensive unit test suite covering solid cube 6 quads, 3D checkerboard 12,288 quads, 16³ leaf-leaf checkerboard 24,576 quads, randomized brute-force area comparison, cross-boundary culling via `buildPaddedSection`, bucket placement (leaves in cutout, glass/water in translucent, stone in opaque), culling rules, log UV orientations, and performance benchmarking.

## Known limitations

- Default light and AO constants are used (`DEFAULT_SKY_LIGHT = 15`, `DEFAULT_BLOCK_LIGHT = 0`, `DEFAULT_AO = 0`, `DEFAULT_TINT_INDEX = 0`) until M05b calculates per-vertex lighting and adds light/AO to the face merge key.
- Faces with no resolved texture get tile index 0; M02c's `tileResolver` must return the sentinel tile for unknown texture names.

## Notes for dependent tasks

- **M02c (Workers & Upload):**
  - Call `greedyMesh(paddedSection, tables)` inside worker. `paddedSection` is an 18×18×18 `Uint16Array` buffer (5,832 entries).
  - Use a `Uint32Array` element index buffer and `gl.UNSIGNED_INT` for draw calls (`gl.drawElements`), because leaf-leaf cutout bucket index counts reach up to 147,456 indices per section ($24,576 \times 6$).
  - Transfer `opaque.vertices.buffer`, `opaque.indices.buffer`, `cutout.vertices.buffer`, `cutout.indices.buffer`, `translucent.vertices.buffer`, `translucent.indices.buffer` back to the main thread.
  - Word 0 vertex layout: bits 0–4=local X (0..16), bits 5–9=local Y (0..16), bits 10–14=local Z (0..16), bits 15–17=normal index (0..5: 0=+X, 1=-X, 2=+Y, 3=-Y, 4=+Z, 5=-Z), bits 18–19=AO (0), bits 20–23=sky light (15), bits 24–27=block light (0), bits 28–31=tint index (0).
  - Word 1 vertex layout: bits 0–15=tile index, bits 16–23=U quad-local block coordinate (0..16), bits 24–31=V quad-local block coordinate (0..16).
- **M05b (Lighting & AO):**
  - M05b will populate `skyLight`, `blockLight`, and `ao` in Word 0 and add them to the face merge key.
