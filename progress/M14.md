## Round 1 review corrections

All seven findings are addressed in one update to `claude/m14`:

1. Each explosion light transaction returns an independent touched-section set, including RGB writes. The `blocksRemoved` listener receives that set directly. A `setBlock` in the final yield cannot clear the explosion's remesh list. The final yield remains for scheduling.
2. Ordinary `processBlockRem`, `processBlockAdd` and `processSkyAdd` loops are identical to master `9a1250d`; ordinary edits allocate no stepped generators. Only explosions use stepped work.
3. Height lookup reads `ChunkSection.palette` directly with uniform-state fast paths and an indexed transparency scan: no palette copies or predicate closures.
4. Blast Charge priming checks only the placed charge, six fire neighbours, or the bounded Current-component neighbourhood. Unrelated edits do not scan merely because Current components exist.
5. The collision axis order is a module constant; neighbour offsets are reused too.
6. Every edit consumer is handled: modified-column persistence; block-entity cleanup; Current updates; fluid scheduling; `blockEdited` listeners (navigation invalidation and charge events); and legacy `onBlockEdited` callbacks. Legacy callbacks receive `batched=true` after lighting. WorldManager handles weather heights, geometry-boundary sections, touched-light/AO neighbour remeshes, and streaming-border/in-flight-light invalidation once through the batch listener, avoiding its ordinary per-block invalidation path.
7. Work contexts refresh lit-column membership and shared references before every step, so streaming light commits and unloads during yields are visible on resume.

No World/Player properties are added or redefined. No other task's tests change in this round.

## Notes for dependent tasks

`World.removeBlocksSteps` writes all blocks before observers and performs one light transaction and one final mesh notification. `WorldListener.blocksRemoved(blocks, touchedSections)` owns the remesh keys; do not read shared engine scratch state after a yield. Legacy `onBlockEdited` consumers can inspect the optional fifth `batched` argument. Ordinary light propagation retains plain loops; changes to propagation rules must keep their explosion-only stepped counterparts consistent. Charge systems are absent while idle. All remote publication uses the GitHub plugin, with no force push or merge.
