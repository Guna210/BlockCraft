## What was built

- **Settings & live UI (`src/engine/settings.ts`, `src/engine/settings-persistence.ts`, `src/ui/settings-screen.ts`)**: Added `fxaa`, `bloom`, and `godRays` booleans defaulting to `false`, normalized/persisted via IndexedDB with clean fallback for older saves lacking the fields, and exposed `"FXAA"`, `"Bloom"`, and `"God rays"` alongside M22b's `"Distant terrain (LOD)"` on the Video tab with immediate live updates and zero chunk remeshing. After merging M22b (15 total Video controls), structured the Video tab into 9 full-width rows at `12 px` pitch (`11 px` control height) plus a 4 px gap and a 3×2 two-column grid of 6 boolean toggles (`Smooth lighting`, `Particles`, `View bobbing`, `FXAA`, `Bloom`, `God rays`) at `13 px` pitch (`11 px` button height, ending at `y = 195`) so every row clears the key-conflict alert line (`y = 204`) and footer buttons (`y = 216`) cleanly without shrinking row pitch below `11 px`.
- **Offscreen bypass & `PostProcessor` (`src/render/post/post-processor.ts`, `src/game/world-manager.ts`)**: When all three toggles are `false`, `WorldManager.drawTerrain()` renders straight to the default framebuffer (`null`) with no offscreen FBO allocation, no extra shader switches, and bit-identical output. When any toggle is enabled, `PostProcessor` lazily owns a canvas-sized `RGBA8` color + matched depth-stencil FBO (recreated on resize) captured via compact `begin()` / `end()` hooks around world rendering (sky, terrain, entities, particles, clouds, weather, selection outline, hand), leaving HUD and DOM UI on `null`, and runs `bloom` → `godRays` → `fxaa`. Review fixes removed the dead `ONE_BUFFERS` constant and preallocated `drawBuf1`, `drawBuf2`, and `godRaysParams` so steady-state `PostProcessor.begin()`/`end()` frames perform no heap allocations once targets and programs are initialized (upstream `WorldManager.drawTerrain()` still calls `sunDirection(ticks)`).
- **`FluidDepth` compatibility (`src/render/fluid-depth.ts`, `src/render/chunk-renderer.ts`)**: Updated `FluidDepth.capture(sourceFramebuffer)` so `gl.blitFramebuffer(DEPTH_BUFFER_BIT)` reads from and restores the active offscreen scene FBO when post-processing is enabled, keeping water depth absorption intact under all toggles.
- **Emissive-only bloom & M22b LOD integration (`src/render/post/emissive-tiles.ts`, `src/render/terrain-fragment.ts`, `src/render/chunk-renderer.ts`)**: Built a startup `64×64` `R8` atlas-tile lookup table on `TEXTURE5` marking only genuinely emissive block/fluid faces (`lightEmission > 0` or lit `lightEmissionWhen` states, excluding unlit shared casing tiles) and compiled lazy `#define BLOOM_EMISSIVE` `ChunkRenderer` variants in the shared `src/render/terrain-fragment.ts` shader (keeping the default no-bloom path identical to `master` alongside `LOD_TERRAIN`). In `ChunkRenderer.render()`, switched to preallocated `drawBuf1` around opaque `lod.draw(false, ...)` and kept `drawBuf1` active for translucent `lod.draw(true, ...)` before switching to `drawBuf2` for `drawTranslucent(...)`, so `COLOR_ATTACHMENT1` (`fragEmissive`) is never left undefined during LOD draws. Quarter-resolution box downsample + 2 separable horizontal/vertical Gaussian blur passes composite subtly over scene color.
- **God rays & FXAA (`src/render/post/sun-visibility.ts`, `src/render/post/post-processor.ts`)**: Overworld-only radial screen-space god rays use the depth buffer far plane (`smoothstep(0.99987, 0.999895, d)`) as a sky mask toward projected `sunDir`, fading with elevation, view angle, daylight/twilight, and rain, and disabling cleanly underwater, in Hollowdeep, and at night. Single-pass luma-based FXAA is implemented from scratch in GLSL ES 3.00 and always runs last when enabled.
- **Debug API (`src/debug/api/postfx.ts`, `src/debug/api/index.ts`, `src/debug/api/core.ts`)**: Added `getPostFx()` reporting active passes, target size, and pass CPU timings (registered alongside M22b's `./lod` in `src/debug/api/index.ts`); toggling uses existing `setSetting`.

## Known limitations

- With `bloom` or `godRays` on and `fxaa` off, the offscreen scene color target is non-multisampled (`RGBA8`), so edges lose the default WebGL context's MSAA.
- The first enable of post-processing compiles its shader programs and allocates offscreen render targets on that frame (`1,174.9 ms` `frameCpuMsMax` measured on SwiftShader during the RD8 all-on flight).
- Hardware GPU timer queries (`EXT_disjoint_timer_query_webgl2`) are not instrumented; `getPostFx().passMs` reports main-thread CPU pass timings alongside `getFrameStats().glCheckMsP95`.
- Full local `npm run verify` was skipped per owner instruction (PR CI runs full verification).

## Notes for dependent tasks

- `WorldManager.drawTerrain()` wraps world draw inside `postProcessor.begin(settings)` / `postProcessor.end(this.postFxContext)`. M22b's LOD passes (`lod.draw(false, ...)` in the opaque pass and `lod.draw(true, ...)` in the translucent pass) run inside `ChunkRenderer.render()` with preallocated single-output `drawBuf1` active while `bloomActive` is true, so `COLOR_ATTACHMENT1` (`fragEmissive`) stays at its cleared zero value without compiling a second LOD shader variant. `FS_CHUNK` in `src/render/terrain-fragment.ts` carries both `LOD_TERRAIN` and `BLOOM_EMISSIVE` defines while keeping the default no-bloom path identical to `master`.
- Keep preallocated state in `PostProcessor` (`drawBuf1`, `drawBuf2`, `godRaysParams`, `activePasses`, `godRaysState`) if extending post-processing passes, and preserve the `null`-framebuffer fast path when all post-fx toggles are `false`.
