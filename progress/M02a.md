## What was built

- `data/blocks/*.json`: Category JSON data files (`terrain.json`, `wood.json`, `ores.json`, `fluids.json`, `special.json`) registering air plus grass block, dirt, stone, cobblestone, sand, gravel, oak/birch/pine logs (with axis state x/y/z), leaves and planks, glass, water, lava, and six Appendix A ores (coal, copper, iron, gold, lumite, skyshard). `special.json` contains only air and glass.
- `src/world/blocks/types.ts` & `src/world/blocks/registry.ts`: Typed `BlockRegistry` loading block data with `import.meta.glob`. Assigns Uint16 block-state IDs in a deterministic order (blocks sorted alphabetically by ID with `air` = 0, state permutations in declared order). Implemented log axis face rotation mapping.
- `src/world/chunk.ts`: `ChunkSection` (16×16×16) with bit-packed palette index arrays (1, 2, 4, 8, 16 bits per entry) and reference counting. Compacts palette back when entries are freed, dropping index array when 1 entry remains (uniform section). Documented byte-accounting method (`getByteSize()`) proving all-air section size is 36 bytes (<= 64 bytes). Zero heap allocations per `getBlockStateId`/`setBlockStateId` call.
- `src/world/column.ts`: `ChunkColumn` managing 20 `ChunkSection`s (y 0–319).
- `src/world/world.ts` & `src/world/world-instance.ts`: `World` class managing `ChunkColumn` map, supporting world-to-chunk coordinate math handling negative coordinates and cross-boundary reads/writes.
- `src/debug/api/world.ts`: Debug API endpoints (`getBlock`, `setBlock`, `fill`) operating on global `World` instance reference, with boundary and error validation. Registered in `src/debug/api/index.ts`.
- `src/render/texture-resolve.ts`: Updated `resolveTexture` to fall back to `<name>_0` when resolving base texture names for animated textures (like `water` and `lava`). Modified M01c code per AGENTS.md §2 to allow fluid blocks in the registry declared with `"water"` or `"lava"` face textures to resolve their base frame from the atlas without failing or falling back to the sentinel rect.
- `tests/unit/chunk.test.ts`: Unit tests verifying palette compaction steps, 10,000-write PRNG round-trip, all-air section size <= 64 bytes, and negative/boundary coordinate math.
- `tests/unit/registry.test.ts`: Unit tests for stable state IDs, unique block IDs/textures, render layers, log face rotations, and error handling.
- `tests/unit/texture-resolve.test.ts`: Added assertions verifying every face of every texture-bearing block in the registry resolves to a valid atlas rect, and that animated base names resolve to frame `_0` without recording missing textures.
- `tests/e2e/m02.spec.ts`: E2E test exercising `getBlock`, `setBlock`, and `fill` debug API methods.

## Notes for dependent tasks

- **Stable State ID Ordering Rule:** Block definitions are sorted alphabetically by block ID, with `air` fixed at ID 0. For blocks with state definitions (e.g. log axis `x`/`y`/`z`), state permutations are generated by sorting state keys alphabetically and iterating values in declared order. M02b, M03b and M17 depend on this deterministic order.
- **World Instance:** Game code manages the `World` instance through `src/world/world-instance.ts`. `getWorldInstance()` creates the `World` lazily if none exists. `src/debug/api/world.ts` interacts with this instance. Note that M02c's `createWorld` debug API method should replace this instance by calling `setWorldInstance(newWorld)`.
- **Animated Textures:** Block registry declarations for fluid blocks specify base texture names `"water"` and `"lava"`. `resolveTexture` falls back to `<name>_0` for base lookups. For M08b fluid rendering, frame animations must index frame tiles explicitly as `<name>_<n>` (`water_0` through `water_31`, `lava_0` through `lava_31`).
