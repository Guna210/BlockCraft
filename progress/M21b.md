## What was built

- Node `ws` server, Vite SSR build and worker entry, CLI, health endpoint and lean
  deployment output. The browser build stays separated by the import boundary.
- Fixed-tick authoritative shared simulation, input/action queues, per-tick
  corrections, reach/break/inventory validation, compressed streaming, recipient
  delta baselines, chat, clocks/weather, keep-alive and ordered delay injection.
- Lazy dimensions, shared portal linking/activation, creature/item/projectile and
  Blast Charge runtimes. Generation and bulk relighting run on Node workers.
- Atomic disk regions containing only edited M17 columns, plus player, block
  entity, item, portal, ECS and scheduled-tick state. Autosave yields between
  records; shutdown waits for saves and pending writes.

## Known limitations

- Full verify is the PR's GitHub CI under the owner's testing override.
- Protocol **v2** rejects v1 clients. Client networking, prediction, menus, name
  tags and chat UI remain M21c, as scoped.
- Server lighting adopts asynchronous shared worker results; a newly edited
  column temporarily answers light queries from its last completed result.
- Inventory transactions currently address the player's owned window **0**;
  arbitrary client window ids are rejected. Chest/kiln state remains server-owned
  and is persisted by its existing block-entity serializers.

## Notes for dependent tasks

### Connecting and ports

- Build/run: `npm run server -- --port 3001 --world ./worlds/default`.
  Text `--seed` is used only for a new world. `--reset-world` removes the selected
  world first. The default port is **3001**.
- Playwright owns **3001** (ordinary) and **3002** (`--delay-ms 150`), with worlds
  under `artifacts/`, reset each run using `blockcraft-test-seed-42`. The preview
  remains **3000**. Readiness is `http://localhost:<port>/health`.
- Connect to `ws://localhost:<port>`. Browser sockets should use
  `binaryType = 'arraybuffer'`. Send `ClientHello` with `PROTOCOL_VERSION` and a
  nonempty unique name. Handle `LoginReject`, `Disconnect` and socket closure.
- Ping/Pong applies while login is loading too: echo Ping ids as Pong. Ping is
  every two seconds; incoming silence expires after fifteen seconds.
- `ServerHello` supplies entity id, seed, position, dimension and absolute time.
  Join also supplies full inventory, time and weather. Portal travel sends a new
  `ServerHello` for the same player id in the destination dimension; clear old
  terrain/entity presentation accordingly.
- `ChunkData.payload` is already deflated M17 column data: use
  `deserializeColumn(payload)`, or inflate once before `deserializeColumnBinary`.
  For Hollowdeep, reset the decoded biome names using
  `column.setBiomeIndices(column.biomeIndices, DIMENSIONS[dimension].biomeIds)`;
  the generic M17 decoder defaults to the Overworld biome table.

### Corrections, actions and inventory

- `PlayerCorrection` is sent **every server tick**, after shared physics, and
  acknowledges the last input actually processed. Input sequence **1** is a
  convenient starting value; acknowledgement 0 can precede any input. Comparisons
  support u32 wrap. Position and velocity are authoritative; reconciliation and
  replay remain entirely client work.
- Send input/look before a related BlockAction. The server preserves that input
  dependency when processing its bounded action queue. Block actions use a
  separate increasing sequence, exact target/face and selected held slot.
- Send StartBreak, then FinishBreak after shared mining time; AbortBreak on
  cancellation. The server independently checks ray, reach, slot, state and
  elapsed time with **100 ms** tolerance. Placement goes through shared rules.
  Rejection sends actual BlockUpdate state (and the neighboring placement cell);
  accepted edits broadcast to everyone with the column loaded.
- Entity attacks come from PlayerInput attack presses and the server's look ray.
- Inventory window **0** has **41** owned slots plus cursor. Send request id,
  current revision and an `InventoryAction`; never apply invented stack contents
  to the server. Match InventoryResult by request id and accept authoritative
  InventorySync revisions. Selection uses SelectSlot with slots 0–8.
- Entity ids are opaque. Maintain each received pose and apply `applyEntityMove`;
  delta baselines are per recipient. Entity messages can arrive while terrain
  streaming is still underway.

### Owning a server in tests

- Node tests can call `startServer({ port: 0, world: tempDir, seed, viewDistance: 1 },
  workerEntry)` from `server/server.ts`; stop with `await server.stop()` in
  cleanup. Raw Vitest source loading should pass a URL to
  `dist-server/generation-worker.js`. Build the server in that test's own setup;
  do not rely on another test file's execution order. See the M21b integration
  test's `beforeAll` and `afterEach`.
- **The M21c "kill the server" E2E must spawn its own process, never kill the
  Playwright server on 3001 or 3002.** After building, use
  `spawn(process.execPath, ['dist-server/main.js', '--port', '0', '--world', tempDir,
  '--seed', 'blockcraft-test-seed-42', '--reset-world'])`. Read the listening port
  from stdout or wait on its health endpoint. Send SIGTERM and await exit for
  clean shutdown/reason tests; abrupt termination requires handling socket close
  without a final reason frame. Always close clients and remove the temporary
  world in cleanup.
- Lean runtime: copy the entire `dist-server/` directory, install only `ws`, then
  run `node dist-server/main.js`. Both entry files, generated assets and the ESM
  package marker are required; the Vite build dependencies stay on the builder.
