## What was built

- Independent creative catalog and local chat overlays, with no idle JS frame work, using the shared palette and existing icon sheet.
- Nine validated commands through direct game-system adapters, local selectors, Tab/Shift+Tab completion and 100-entry history. Errors become HUD messages. Fill validates a 4,096-block cap before editing and yields work in small batches; ore searches yield between columns.
- Screenshot capture immediately after the WebGL render, with a temporary PNG blob download link. No network requests or global drawing-buffer preservation.
- Central keybind actions and a third Settings key tab for Chat, Command and Screenshot, persisted/remapped by M18b's existing settings model.

## Known limitations

- Chat is local; multiplayer belongs to M21.
- Coordinates are absolute decimal numbers. Fill coordinates are integers within world height 0–319; fill is limited to 4,096 blocks.
- Locate retains existing bounded searches: structures within 2,000 blocks, ores within eight chunks. Flat worlds have no ore.
- PNG downloads contain the WebGL canvas, excluding DOM overlays. Links expire after two minutes or are replaced by the next screenshot.
- Browser pointer-lock refusal is handled by leaving the pointer unlocked until the next canvas click.

## Notes for dependent tasks

- `src/game/commands/parser.ts` owns pure parsing, selectors, bounds and completion. `executeCommand` accepts a `CommandContext`; `runtime.ts` adapts that to the active game systems. There is no dependency on `window.__blockcraft`.
- `src/ui/chat.ts`, `creative-inventory.ts` and `screenshot.ts` own UI lifecycle. Main wires them; UiManager has a creative-inventory open callback. Survival inventory and HUD implementations are unchanged.
- Shared ore/structure locate code now lives under `src/game/commands/`. Existing debug modules retain registration and ore exports. Synchronous debug ore locate drains the same generator that console locate advances between yields.
- `entityTypeIds()` returns a snapshot for completion. No creature registrations, models, AI, spawn behavior or hot object shapes changed; `/summon` uses the existing `spawnEntity` registry including registered families.
- Other-task edits: M18b keybind/settings additions; M09b UiManager routing callback; M18a/main lifecycle and post-render screenshot hook; M03e/M19a debug locate wrappers and extended M03e unit source guard; M13a read-only entity type accessor.
- No harness, owner files, item/block data or dependencies changed. First push requires the publish gate in CLAUDE.md. Verified status/title require green PR CI.
