# M16b — Audio integration decisions

1. **One runtime audio service.** `src/audio/service.ts` owns playback on top of M16a recipes and the M16c composer. Game code calls `sound.play(id, { pos?, priority? })`. M14 explosions use the same service's scalar `enqueueExplosion` fast path; both paths share its buffers, voices, mixing and coalescing, with no separate synthesis path.
2. **Gesture activation.** The service creates and resumes its `AudioContext` on the first pointer or key gesture. Before that, `play()` records the sound ID in `lastSounds` and returns without creating audio nodes.
3. **Spatial playback.** Positional voices use HRTF panners with inverse distance attenuation. The listener follows the camera once per rendered frame. A reusable voxel raycaster checks occlusion every four simulation ticks per voice and ramps a low-pass filter when a solid block is found. Listener/ray scratch state is reused.
4. **Voice budget.** Playback is limited to 32 active voices. Priority is importance multiplied by inverse distance falloff. At capacity, the service steals the lowest-priority voice only when the new voice is more important; otherwise it drops the new voice.
5. **Game events.** Footsteps use the surface beneath the player and walked distance for cadence. Break/place, pickup, eating, hurt/death, explosion, rain, delayed thunder, nearby fluid, lit kilns, pistons, button/lever, bow, arrow, Note Block, and creature idle/hurt/death events use named recipes through the service. Creature idle cadence uses a seeded random stream and respects hearing range. Environmental loops are polled at tick cadence and produce no voice when no source is audible.
6. **Cave ambience.** Underground with low sky light, the service raises a shared reverb send smoothly and schedules occasional eerie cues from a seeded stream.
7. **Music scheduling.** M16c sequences are played as a single music voice at seeded random intervals with silence between pieces. Mood comes from the current biome in the overworld or `player.dimension` elsewhere. Pieces fade in and out.
8. **Volume model.** The master output multiplies the existing live `masterVolume` and category gains for `music`, `effects`, and `ambient`. No new UI is added.
9. **Debug stats.** A separate `src/debug/api/audio-stats.ts` module exposes `getAudioStats()`, returning `{ contextState, activeVoices, lastSounds }`. `lastSounds` is a bounded 64-entry ring and the API is registered with one line.
10. **Acceptance tests.** M16b owns the four M16 E2E criteria: gesture activation, material-specific footsteps, break plus Blast Charge explosion IDs, and a 27-charge chain staying at or below 32 voices. The chain test uses the debug fill/prime APIs. M12's rain test gains an assertion for `weather.rain` in `lastSounds`.
