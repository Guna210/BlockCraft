# M07b — Drops, inventory and particles

## Owner decisions

The builder prompt directs category JSON item and loot registries; a block item for every block; only the required tools and referenced harvest tiers; 36 inventory slots, hotbar 0–8 and a selected slot; storage and debug access without M09 UI; selected tools for Appendix A.1; selected block placement with survival consumption and the empty-slot M07a held-block fallback; harvest-gated drops with stone → cobblestone and logs → themselves; no creative drops; a dedicated item manager rather than M13a's ECS; fixed-tick gravity, drag and shared collision shapes; random pops, equal-stack merging within 0.5, magnetic pickup within 1.5 if the stack fits, expiry at 6000 ticks; rotating/bobbing atlas cubes and procedural item sprites with world lighting; 12–16 textured, lit short-lived break quads; fixed pools and batched draws without per-frame allocations. Worker sizes and terrain draw cadence are unchanged. Sky/cloud source belongs to the concurrent M12b builder and is untouched.

## Implementation

- `data/items/` mirrors block categories and adds tools separately. Tool definitions supply type, harvest level and speed. Pickaxes cover wood, stone, copper and iron because current block metadata references levels 0–3. Wooden axe/shovel/hoe and iron shears cover the other referenced tool kinds. Further items, crafting, wear, equipment and UI remain with their introducing tasks.
- `Inventory` owns 36 slots and selected slot validation. Existing `Player.selectedSlot` delegates to it. Insertions merge existing stacks first, then use empty slots, atomically rejecting overflow. Reusable slot records avoid allocating during pickup. Debug snapshots are detached copies. `selectHotbarSlot` is a documented debug helper; M09c owns physical scroll/number selection and HUD.
- Mining shares `canHarvest` with the Appendix A.1 duration function. The completed break callback receives the original state and selected tool. Placement consumes only after successful world edit and only in survival. A selected non-block item cannot place. Empty-slot fallback retains M07a behavior. Creative middle pick updates an occupied selected slot to the targeted default block item, while empty selection retains the held-block fallback.
- Loot tables cover ordinary self-dropping blocks and stone's cobblestone/grass-block's dirt transformations. Air, fluids, Foundation Stone and glass have no tables. Leaf saplings/apples and ore resources are not introduced here; their introducing tasks add their items and appropriate loot tables. The tables do not manufacture resource items outside this task.
- Item manager has 256 reusable records, monotonically increasing per-world IDs and a world-seeded RNG stream. The 0.25-block entity body uses `BlockCollision.sweep` with an optional half-width; its original default preserves all player behavior, including slab shapes. Gravity is 12 blocks/s², drag 0.96 per tick, terminal fall speed 20. Unloaded columns freeze movement while age continues. Equal stacks merge within 0.5 up to their declared maximum; the older age persists. A four-tick spawn grace permits a visible pop. Within 1.5 blocks of the player's body, a fitting stack attracts through ordinary swept physics and transfers only at close distance. Walls therefore stop magnetic movement. Expiry is exactly 6000 ticks. The bounded spawn API returns null on exhausted capacity.
- `getEntities` lives in the entities debug domain, returns SPEC fields plus item/count/age and accepts type/radius filters. M13a can combine these plain snapshots with ECS queries and reserve the ID namespace when it migrates the manager. Inventory and entity registration each occupy one import in the index.
- Break debris uses 512 reusable records and a separate seeded RNG. Each break emits 16 fragments; fragments sample a 3×3 pixel patch from one original block face. Lifetime is 18–22 ticks, with gravity and drag. The circular visual pool replaces old debris at capacity.
- Drop rendering caches state-face atlas rectangles at initialization and writes into one persistent CPU array and GPU dynamic buffer. One item submission draws all 0.3-block cubes and 0.36-block rotating sprites; one particle submission draws camera-facing quads. Bob amplitude is 0.1 block. Physical positions interpolate between ticks; paused debug advancement renders the latest tick. Light reads the existing sky/block storage without allocating light-result objects. WebGL2's buffer upload offset/count overload avoids per-frame subarray objects. Opaque faces retain the terrain atlas's encoded grass-side dirt alpha. Procedural tools use declared palettes, clustered silhouettes, top-left shading and deterministic pixels. All resources use GLWrapper and its existing error checks.
- WorldManager draws these batches at the existing entity callback between cutout and translucent terrain, and corrects triangle diagnostics for the actual mixed geometry. Its old player-render callback assumes 12 triangles per draw; item/particle triangles are counted separately. No terrain draw is gated or skipped.
