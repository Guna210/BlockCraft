# M18c — Creative inventory, chat & commands

## Owner decisions

1. Chat (`T`), command (`/`) and screenshot (`F2`) are actions in M18b's central `src/engine/keybinds.ts` map. Settings remaps them; gameplay does not check those physical keys directly.
2. The inventory action opens a separate creative inventory in creative mode. Categories, search across every registered item, inexhaustible catalog stacks and a delete slot belong to that screen. Searching `glass` includes only matching items regardless of the active category. Survival inventory keeps its existing implementation.
3. Chat is local only. Messages and command errors appear as fading HUD lines. Tab completes names and arguments, Up/Down recall history and restore the draft. Opening chat captures input before gameplay sees it and releases pointer lock.
4. `/tp`, `/time set`, `/weather`, `/give`, `/gamemode`, `/seed`, `/fill`, `/locate` and `/summon` use game systems directly. `@s` and `@p` both select the player. Unknown commands and invalid arguments return error messages. Fill has a volume cap. Summon delegates to the live entity registry without registering or replacing types. Locate supports structures and ores.
5. Screenshot capture happens immediately after rendering the canvas, using `toBlob('image/png')` and a generated blob download link. It makes no network requests and does not enable `preserveDrawingBuffer`.
6. New functionality lives in `src/ui/creative-inventory.ts`, `src/ui/chat.ts`, `src/ui/screenshot.ts` and `src/game/commands/`. UiManager and main contain only routing and lifecycle integration. The entity registry gains only a read-only snapshot accessor for completion; its registrations and spawning behavior are unchanged.
7. Chat and creative inventory have no frame hook, idle timer or per-frame allocations while closed. They never add or redefine properties on World, Player or other hot shared objects.
8. Automated evidence includes commands typed through chat, creative search, parsing, selectors, completion, the fill cap, screenshot downloads and remapping. Visual evidence belongs in `docs/screenshots/M18c/`.

## Implementation decisions

- **Inventory:** five tabs (All, Blocks, Gear, Food, Materials), 36 catalog items per page, 36 player storage/hotbar slots, and a cursor preview. Left click takes a maximum stack; right click takes one. Taking from the catalog never removes an entry. Player slots use existing inventory operations. Delete discards the cursor; closing returns it to inventory and discards creative overflow. No blocks, items, textures or icon generators were introduced.
- **UI:** the shared eight-color palette, bitmap font, bevels and icon sheet draw the creative panel; transparent DOM hit targets provide real button/tab roles. The search input and chat use local browser monospace controls. Settings gains KEYS 3 so the new bindings fit without overlapping the footer.
- **Console:** commands accept whitespace-separated tokens, decimal absolute coordinates and exact argument counts. Selectors are validated before mutation. History is capped at 100 entries, messages at eight, and each message fades over ten seconds while chat is closed. Tab/Shift+Tab cycle stable completion strings. Editing or history navigation resets the completion cycle.
- **Fill:** inclusive bounds, reversed corners accepted, integer coordinates, Y 0–319, maximum 4,096 blocks. Validate everything before touching the world. Work yields after 128 block edits or four milliseconds of editing and cancels if the world/player changes.
- **Locate:** shared ore and structure algorithms were extracted from debug modules into command helpers. Debug modules retain their registration and exports. Structures use the existing 2,000-block search limit; ores retain the existing eight-chunk radius and nearest-position ordering. Console ore search yields between columns; synchronous debug locate drains the same generator. Existing loaded blocks, including mined ore, remain authoritative.
- **Summon:** optional absolute position defaults to the player. The command does not filter by a fixed creature list: `spawnEntity` accepts any registered type or family, including `item:<id>`. Completion reads `entityTypeIds()` plus registered items for the item family.
- **Screenshots:** one pending capture at a time; a subsequent result revokes the earlier blob URL, and the link expires after two minutes. The PNG contains the WebGL game canvas, as requested; DOM overlays are outside that canvas.
- **Lifecycle/input:** capture-phase key handling stops propagation while typing or browsing creative inventory. Existing InputEngine capture clears held actions. Closing requests pointer lock again only if the screen released it. Death closes these overlays before displaying the death screen.
- **Verification:** follow the owner's override: `MILESTONE=M18 npm run verify:quick`, plus E2E for touched milestones. Do not run full local verify. Full verify: PR CI. The first push waits for the publish gate in CLAUDE.md; final verified status/title wait for green CI.
